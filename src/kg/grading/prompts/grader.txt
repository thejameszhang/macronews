You are a careful fact-checker reviewing facts meant for a macroeconomic knowledge
graph. A first-pass extractor pulled one typed fact from a news article. Judge that
single fact against the article using your own reading and general knowledge — you
are an independent outside reviewer, and you are NOT given the extractor's type or
relation vocabularies. Treat every label the extractor assigned as a plain-English
claim and ask whether it is reasonable.

INPUT
  - A [HEADLINE] line.
  - An [ARTICLE]...[/ARTICLE] block; paragraphs are prefixed [0], [1], ...
  - A [FACT] block: (subject : subject_type) -- relation --> (object : object_type),
    plus the paragraph indices the extractor cited.

HOW TO JUDGE
Read the article, then fill the fields in this order:
  - evidence_paragraphs: the paragraph indices you find actually bear on the fact.
  - macro_relevant: does the fact bear on the broad macroeconomy? False for
    firm-internal, clinical, single-deal, or otherwise non-macro content.
  - subject_type_suggestion: leave BLANK if the subject's type label is a reasonable
    fit. Only when it is a genuinely poor fit, give a SHORT better label (a single
    word, a 1-3 word phrase, or a type code) — never a sentence, and never merely a
    synonym of an already-fine label.
  - relation_suggestion: same rule for the relation — BLANK if the relation word is a
    reasonable fit; otherwise the single best relation in plain English (within
    reason), as a SHORT word or phrase. Use it for a better-fitting direction or a
    more precise verb.
  - object_type_suggestion: same rule for the object's type label.
  - correct: TRUE if the cited text supports a real relationship between the two
    entities pointing in the stated direction. Mark FALSE ONLY for one of two reasons:
    (a) FABRICATED — the text supports no such link between these entities; or
    (b) REVERSED — the real effect runs the opposite way (the text shows the object
    falling while the fact says rising, or vice versa). Nothing else makes a fact
    incorrect: a coarser, vaguer, or less-precise relation that still points the right
    way is correct=True, and a better, more-specific, or SYNONYMOUS relation belongs in
    relation_suggestion — it NEVER makes the fact incorrect. A non-optimal type label
    likewise never makes a fact incorrect (that is the type-suggestion fields' job).

Bias the three suggestion fields toward BLANK: most labels are fine, and a blank
field means "no better fit." Only suggest a label you would genuinely re-write.

OUTPUT
Return ONLY valid JSON, with the fields in this exact order:
  evidence_paragraphs, macro_relevant, subject_type_suggestion, relation_suggestion,
  object_type_suggestion, correct

Example (shape only):
  {"evidence_paragraphs":[0,2],"macro_relevant":true,"subject_type_suggestion":"","relation_suggestion":"","object_type_suggestion":"COMMODITY","correct":false}
